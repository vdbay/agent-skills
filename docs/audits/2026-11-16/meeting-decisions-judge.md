## What works

- **A real output contract, not a vibe.** `SKILL.md:134-158` fixes the H1, six section headings, metadata fields, decision-status vocabulary, action-status vocabulary, three-integer decision count, exact table headers via the template, empty-section markers, and placeholder-to-uncertainty cross-references. `assets/output-template.md:17-61` supplies the headers and row shapes, and `scripts/validate-output.mjs` enforces them. This is the main reason the skill is production-usable.
- **Decision quality is treated as the hard part.** The three-part test (`SKILL.md:55-65`) separates commitment, specificity, and acceptance; the conflict ladder (`:67-76`) distinguishes explicit supersession, scope differences, conditional decisions, and genuinely unresolved conflicts; the guide's four worked patterns (`references/extraction-guide.md:78-116`) show the intended handling rather than saying "use judgment."
- **Uncertainty is a first-class output, not a disclaimer.** Missing owners and dates must use `Unassigned — confirm`/`No date — confirm` and get an uncertainty row (`SKILL.md:88-95`, `:158`); the guide's uncertainty catalogue (`references/extraction-guide.md:138-153`) turns each gap into a work item. The skill explicitly refuses to default to the chair, the speaker, or the most senior person (`SKILL.md:164`), and refuses to resolve conflicts with org-chart knowledge (`:165`).
- **Evidence discipline.** Every row is supposed to trace to a locator, a short quote, and a speaker; invented line numbers and transcript dumps are banned (`SKILL.md:53`, `:170-171`; `references/extraction-guide.md:128-136`). The redaction rule for credentials/customer identifiers (`SKILL.md:172`) is a good safety addition for operations transcripts.
- **The gotchas are earned.** The list at `SKILL.md:160-173` contains the exact mistakes a generic summarizer makes: "we discussed" as a decision, "let's" without acceptance, pronouns as owners, outside knowledge as conflict resolution, relative dates without a meeting date, "revisit" as reversal, and speaker labels taken as truth. This is not generic filler.
- **Fresh-context evidence.** I ran eval 1 and eval 2 in fresh `opencode run` sessions with only the skill and fixture. Eval 1 produced a valid brief with reciprocal D-05/D-06 statuses and C-01; eval 2 produced a valid no-date Teams brief using `no locator` throughout, no invented Vendor A decision, and explicit uncertainty. Both passed strict validation. This is stronger evidence than the README's self-report and shows the skill does not require the author's context.

## What to fix next

1. **Make eval 1 independent and align eval 2's expected output with its assertions.** `evals/fixtures/ops-sync-2026-11-10.txt:31-75` reuses the same QuickShip/Northwind supersession and the same Marcus/Elena returns-portal conflict as the worked examples in `references/extraction-guide.md:82-102`; an executor can pass by recalling the guide rather than transferring the rules. Replace eval 1 with a distinct domain/name/conflict shape, or add a third eval that does not mirror the guide. In `evals/evals.json:24`, change "records only the process decision" because the assertions (and a defensible extraction) allow the separate no-migration decision; change assertion 2's "run a two-week spike or defer tool selection" to "run a two-week spike and defer tool selection" so a one-part answer cannot pass. In eval 1, allow the supersession assertion to be satisfied by the D-02 `Superseded by D-03` status or the D-03 evidence, not only the rationale/decision text; the correct fresh output placed it in the evidence/status. In eval 2, make assertion 7 accept Q-02's wording ("Who will be named...") or require a literal "not yet named" sentence, rather than leaving the grader to infer the rule.
2. **Add a with/without baseline and ship the evidence.** `README.md:66` says the without-skill baseline was not run, and `README.md:63-67` cites sample briefs that are not in the folder. Add an `evals/results/` or `benchmark.json` with with-skill/without-skill pass rates, and ship the valid, empty, and broken sample briefs or a small test script so the validator claims can be rerun. This is the largest remaining gap in the evaluation category.
3. **Close the validator's false negatives.** `scripts/validate-output.mjs` currently accepts an owner of `Unknown`, an owner of `ops`, a multi-owner action (`Priya and Marcus`), a `Needed by` of `Friday` in Open questions, an invalid calendar date such as `2026-13-45`, and a conflict row with no quote; all of these passed `--strict` in judge-built variants. The exact placeholders are the skill's core promise, so enforce them (`:52`, `:328-342`, `:392-415`, `:546-549`): reject `Unknown`/`none`/`TBC`, treat `ops` as unassigned per `references/extraction-guide.md:48-55`, reject multi-owner cells (or require them to be split), validate `Needed by`, validate real dates, and require a quote/locator in conflict positions. Add regression fixtures for each.
4. **Resolve the contract inconsistencies.** `assets/output-template.md:19` says "One sentence starting 'We will ...'", but `references/extraction-guide.md:112-116` requires prior superseded decisions to be retained; a prior decision cannot be "We will". Change the template to "One sentence; use 'We will' for a decision made in this meeting, and past/conditional wording plus provenance for a superseded prior decision." `SKILL.md:33` allows pasted text, but `:35` only defines a source-stem path; add a pasted-text default (for example `meeting-decisions.md` in the working directory). Define `Prepared` as the date the brief is generated, not the meeting date. Add the "only if the commitment is made in this meeting" qualifier to the "I've told legal we're moving" signal at `:63`, matching `references/extraction-guide.md:21`. Define when the `Done` action status (`:154`) is used, since `:85` says to omit completed work. Finally, decide whether `Unassigned — confirm`/`No date — confirm` in Open questions require uncertainty rows: `SKILL.md:158` limits the rule to decision/action tables, while `references/extraction-guide.md:142-151` implies every missing owner/date is a gap; fresh eval 2 left Q-02's `No date — confirm` without a U row and passed. Also define `-v3`/`-vN` behavior when `<name>-v2.md` already exists; the current rule protects the original but can overwrite a prior revision.
5. **Allow a short summary for genuinely empty meetings.** `scripts/validate-output.mjs:278-285` warns whenever the summary is outside 80-120 words, and `SKILL.md:128` says fix every warning. A 46-word accurate summary for a no-decision/no-action meeting failed strict with 0 errors/1 warning. Add a lower bound or a non-strict exception when decision and action counts are zero; otherwise the skill forces filler, which contradicts its own "no generic filler" stance.
6. **Make the acceptance rule teachable.** `SKILL.md:61` says acceptance is satisfied if "the speaker has authority to make it, or the group accepts it without objection", while `references/extraction-guide.md:30` says even a senior person's idea is a proposal until treated as settled. Add explicit acceptance examples ("Fine", "Works for me", accepting a follow-up track) and state that authority alone is not enough unless the statement is treated as settled. Fresh eval 2 needed this inference for "Let's run a two-week spike" followed by "Fine" and task acceptance.
