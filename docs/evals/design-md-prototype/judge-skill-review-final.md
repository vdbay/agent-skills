## What works

- **The method is genuinely brand-agnostic.** Searching `SKILL.md`, `references/`, and `assets/` for Gojek, GoRide, Maison, `#00AA13`, and `gojek.com` returns no matches; brand-specific material appears only in the README's evaluation-status section, `evals/results`, and the applied prompt. The instructions tell the executor to replace every placeholder with current-brief evidence (`SKILL.md:15-17`).
- **The three-part deliverable is actionable.** The output contract (`SKILL.md:21-37`) names `DESIGN.md`, `index.html`, `design-md.html`, `README.md`, `sources.md`, and the evidence files. Phases 3 and 4 give enough detail to build each one, and the applied package shows the result is real: 106 KB `index.html`, 126 KB `design-md.html`, a valid eight-section `DESIGN.md`, and 20 non-blank screenshots. The spec page visibly implements token grids, type specimens, spacing, elevation, shapes, components, motion, do/don't pairs, a source excerpt, and an evidence footer.
- **The collaboration and context-isolation protocol is credible on paper.** `references/collaboration.md:5-35` defines orchestrator, researcher, builder, verifier, and judge, explicitly forbids combining builder and final judge in one context, and lists what the judge must not receive. Handoff 4 (`:89-98`) excludes `evidence/judge`, previous scores, `checks.md`, and author rationale. The blank judge template contains a contamination declaration and the applied judge report repeats it.
- **The official gates are strong and reproducible.** Fresh `designmd lint` produced 0 errors, 0 warnings, 1 info; fresh CSS export matched `evidence/export.css` exactly; the strict artifact validator passed; both Lighthouse reports score 1.0; the browser matrix records 20/20 cells at 320/390/768/1024/1440 × light/dark; 20 screenshots exist with the expected names and non-trivial sizes.
- **The applied provenance is unusually concrete.** `sources.md` records retrieval dates, rights, conflicts, rejected sources, GitHub stars/licences/last-push, and the `gojek.io` HTTP 429. I independently confirmed `gojek.design` returns 200, `gojek.io` returns 429, `google-labs-code/design.md` reports 28,896 stars/2,308 forks/Apache-2.0, and the cited Gojek repositories match their current star/licence/push metadata.
- **The requested fixes are largely present.** `--out` writes the static report after reading and a temporary run confirmed it; BOM-prefixed evidence passes strict; the judge packet archived as `with_skill/outputs` contains no `evidence/judge` and the artifact README does not claim a score; the hard-pass category floor appears in `SKILL.md:48`, `SKILL.md:291`, `references/judge-rubric.md:13-17`, and `assets/judge-report.template.md:32-33`; the official CLI’s default lint output is JSON, matching `references/design-md-spec.md:131` and the fresh run.

2. **`SKILL.md:156-168` and `references/design-md-spec.md:165`** — make the JSON capture example match the warning. Do the same for the lint-unavailable path: define an accepted JSON shape such as `{ "summary": { "errors": null, "warnings": null }, "notRun": "reason" }` and make the validator’s warning deterministic.
3. **`evals/results/iteration-1/gojek-applied/`** — re-judge the final artifact after the six fixes, or state plainly that the 92/100 report predates them. The report is at 17:25; `index.html`, `design-md.html`, and `README.md` were modified at 17:32–17:39, and the evidence at 17:37–17:38. A post-fix judge report (or a “pre-fix score” note in `RESULTS.md` and the README) is needed before the 92 can describe the current tree. Also update the artifact README’s “separate judge is scheduled” sentence now that the report exists; for a blind packet, omit the sentence or point to `evidence/judge/` and state that it is excluded.
4. **Eval coverage** — run at least one of the remaining `evals.json` cases, preferably case 1 (single-property, proprietary font) or case 4 (vague brief, no brand book), in a fresh context. A single applied Gojek case proves the workflow can produce a strong multi-property package; it does not exercise the single-property or concept-label paths. 5. **`evals/results/iteration-1/gojek-applied/with_skill/outputs/README.md`** — either copy the 20 screenshots into `outputs/evidence/screenshots/` or change the file map to point to the sibling `with_skill/screenshots/`. 6. **`gojek-design/README.md:37`, `gojek-design/DESIGN.md:484`, `gojek-design/index.html:2123-2131`** — the applied artifact still has evidence-honesty residuals: the README says evidence adds “about 1.7 MB” when the evidence files total about 0.85 MB and screenshots about 14.5 MB, not 13.8 MB; the motion curves are still attributed to `[S1]` rather than the motion source `[S14]`; and the `.cta-panel h2` heading uses `line-height: 0.98` / `letter-spacing: -0.045em` while the `brand-hero` token is `0.95` / `-0.03em` (the main `.hero h1` at `:593-599` now matches the token). If the CTA heading is a deliberate campaign variant, document it; otherwise align it. These do not invalidate the skill, but they are exactly the sort of drift the judge report asked to remove.
7. **Optional validator improvement** — add a check for CSS values that bypass the DESIGN.md custom properties (the current `checkTokenReuse` only verifies that some hex values appear in the HTML, not that component CSS consumes the token variables). The applied hero-token drift was caught by the judge, not by the static validator. This is a non-blocking improvement, not a reason to fail.

## Score rationale

This is a strong, coherent skill with real verification and honest reporting. The core method is brand-agnostic, the official-format workflow is specific, the two HTML deliverables are well specified, and the applied Gojek package proves the method can produce a lint-clean system with a distinctive prototype and a living spec. The skill does not overclaim a baseline: the absence of a no-skill comparison and the manual-testing gaps are explicitly recorded. The score is held below 15/15 on evaluation evidence because one applied run is not a controlled benchmark, only one of four eval cases was run, and the judge score predates the final artifact edits. The remaining documentation issues (the stale `README.md:62` results line and the redirection/BOM inconsistency) are small but real, so instruction and maintainability are not full marks. Nothing here is a critical fail: every required artifact exists, the core output is verifiable, and the skill works without the author’s conversation context.
